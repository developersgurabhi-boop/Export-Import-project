# TMS Backend: Complete Specification

Scope: everything for the backend of the Transport Management System (NestJS API + worker, PostgreSQL, queues, GSP/E-Way Bill integration, documents, security, testing, deployment, backlog). Items marked [CONFIRM] are unconfirmed business or tax assumptions; the stated default is used until confirmed.

---

## 1. Overview

- Multi-branch transport company, one organization now, multi-organization ready.
- Covers: users with role and branch permissions; masters; rate cards and freight calculation; LR (manual or from E-Way Bill); E-Way Bill lifecycle via GSP/NIC; challans (multi-LR); one GST invoice per LR; payments (partial, allocations); reports; document PDFs; audit log.
- Architecture: modular monolith, two processes (API, worker) from one codebase and image, one PostgreSQL database (business data, queue, audit).

## 4. Code structure

```
apps/server/
  src/
    main.api.ts            HTTP
    main.worker.ts         pg-boss consumers + schedulers
    modules/<name>/{api,application,domain,infra}/ + index.ts
    platform/              db, outbox/queue, config, logging, idempotency, numbering, errors, request-context, policy
    shared/                money, dates, financial-year helpers

  test/{integration,e2e}/
```

Modules: identity, organization, masters, rates, lr, eway, challan, billing, payments, documents, reports, audit.

Rules: controllers call application services only; domain has no framework or DB imports; modules import each other only through index.ts; each module owns its tables; repositories never call other modules' repositories; Prisma client is forbidden outside infra/ and platform/ (lint); only the eway module knows GSP payloads.

## 5. Conventions

- Naming: DB snake_case singular tables, FK `<table>_id`; TS PascalCase types, camelCase vars, kebab-case files; API plural kebab-case nouns, actions as sub-resources (`POST /lorry-receipts/{id}/book`); permissions `<resource>:<action>`.
- IDs: UUIDv7 generated in app. Business numbers are separate columns assigned at finalize.
- Time: instants `timestamptz` UTC; business dates `date` in Asia/Kolkata; financial year Apr to Mar labelled `26-27`; fyOf(date) unit tested at 31 Mar / 1 Apr.
- Money: NUMERIC(15,2) amounts, NUMERIC(12,4) rates and percentages, NUMERIC(12,3) weights. Round half-up at defined points (per line, then invoice total, plus explicit round_off to nearest rupee [CONFIRM]); store results; never recompute issued values.
- API: errors RFC 7807 with stable `code`; keyset pagination `limit` + `cursor` returning `{items,nextCursor}`; editable resources carry `version` (mismatch = 409 CONCURRENT_MODIFICATION); X-Request-Id on every response; unknown request properties rejected.
- Logging: pino JSON with requestId, orgId, userId, branchId, module, durationMs. Secrets and tokens redacted by allow-list serializer.
- Git: trunk-based, branches `feat/<module>-<desc>`, Conventional Commits, squash merge.

## 6. Platform layer

### 6.1 RequestContext
AsyncLocalStorage populated by the auth guard (requests) and job wrapper (jobs). Fields: requestId, orgId, userId, permissions, branchScope, isHeadOffice, ip, userAgent. getContext() throws if absent.

### 6.2 TxManager
`run(fn, opts)`: opens transaction, `SET LOCAL app.org_id / app.user_id / app.request_id`, default timeout 5 s (max 15 s for marked operations). No HTTP, S3, GSP, Gotenberg or email inside a transaction; enqueue a job instead. Keep Prisma pool at 5 to 10 per task; add RDS Proxy before scaling past about 10 tasks.

### 6.3 Authorization
- `@RequirePermission('lr:create')` on every route; deny by default; a startup test scans routes and fails on any without a declaration.
- Reads: filter `branch_id IN (branchScope)`; writes: `policy.assertBranchAccess(branchId)`.
- LR visibility [CONFIRM]: `origin_branch_id IN scope OR destination_branch_id IN scope`; head office sees all.
- MFA-required permissions: user:manage, org:manage, eway:cancel, invoice:cancel, payment:reverse, report:financial (token claim mfa=true).
- Token claims: sub, orgId, sid, mfa, iat, exp. Permissions and scope are loaded per request with a 30 to 60 s in-process cache, invalidated on role change.
- Out-of-scope entities return 404, never 403.

### 6.4 Idempotency
Table idempotency_key(org, scope, key, request_hash, state, response_status, response_body, expires_at 48 h). Required header on guarded POSTs. Flow: insert IN_PROGRESS inside the business tx (ON CONFLICT DO NOTHING); same key + same hash returns stored response with `Idempotent-Replayed: true`; different hash = 422 IDEMPOTENCY_KEY_REUSED; in-progress = 409 REQUEST_IN_PROGRESS; store response before commit. Nightly purge job.

### 6.5 Numbering
`NumberingService.next(tx, {orgId, docType, scope, fy})` does `UPDATE document_sequence SET last_number = last_number + 1 WHERE ... RETURNING last_number` in the caller's transaction (rollback rolls back the number; no gaps). Series row created on first use. Scope: GST registration for invoice and credit note; branch for LR, challan, receipt [CONFIRM]. Template tokens `{BR}`, `{FY}`, `{SEQ:5}`, e.g. `BR01/26-27/00123`. Validate at configuration time: max 16 characters, only letters, digits, `/`, `-`. Numbers assigned only at finalize. Never use Postgres SEQUENCE for statutory numbers.

### 6.6 Queue (pg-boss)
Producers pass the active transaction (atomic with business change). Defaults: retryLimit 8, retryDelay 30 s, retryBackoff true, singletonKey where one in-flight job per entity is needed. Handlers must be idempotent. Failed jobs after retries are surfaced in /ops/failed-jobs.

| Queue | Purpose | Notes |
|---|---|---|
| eway.generate | Generate E-Way Bill | singletonKey `eway:<gstin>:<docNo>` |
| eway.update-vehicle | Part-B update | per EWB |
| eway.cancel | Cancel EWB | per EWB |
| eway.reconcile | Resolve UNKNOWN outcomes | every 10 min for open UNKNOWN |
| eway.sync-status | Refresh validity/status | hourly for active EWBs |
| doc.render | PDF render to S3 | concurrency = PDF_CONCURRENCY |
| report.export | Large exports | result in S3 |
| maint.purge-idempotency | Delete expired keys | nightly |
| maint.audit-partitions | Create next month's audit partition | monthly, ahead of time |

### 6.7 Audit
Interceptor records successful mutating requests; use cases call `audit.record({action, entity, entityId, before, after, reason})` for finalize, cancel, reversal, permission change, secret read. Append-only; changed fields only; never include credentials or tokens.

- lr and invoice: BEFORE UPDATE raises DOCUMENT_IMMUTABLE when OLD.status is not DRAFT and a protected column changes. ## 8. Business rules and state machines

Every transition is a pure domain function `transition(entity, action, ctx)`; services never set status directly; each transition writes history or audit.

### 8.1 LR
| From | Action | To | Preconditions / effects |
|---|---|---|---|
| new | create | DRAFT | lr:create + branch access |
| DRAFT | book | BOOKED | parties, billing party, locations, at least one item, weight > 0, rate resolved or overridden; assigns LR number, snapshots parties, stores freight breakdown, enqueues doc.render and eway.generate if configured |
| BOOKED | dispatch | IN_TRANSIT | active challan, vehicle assigned (via challan dispatch) |
| IN_TRANSIT | arrive | ARRIVED | destination branch or challan arrival |
| ARRIVED/IN_TRANSIT | deliver | DELIVERED | POD optional; sets delivered_at |
| BOOKED/IN_TRANSIT/ARRIVED | cancel | CANCELLED | lr:cancel, reason, no active invoice, not on active challan, E-Way Bill cancelled or absent; number not reused |
Drafts are discarded by soft flag only. [CONFIRM] whether To-Pay LRs may be invoiced before delivery.

### 8.2 Challan
DRAFT to DISPATCHED (at least one BOOKED LR, vehicle set, valid E-Way Bill Part-B vehicle where needed, hire fields valid, LR not on another active challan; assigns number; LRs to IN_TRANSIT) to ARRIVED to CLOSED. DRAFT or DISPATCHED to CANCELLED (reason; LRs revert to BOOKED). Vehicle change after dispatch enqueues eway.update-vehicle for every active EWB.

### 8.3 Invoice
create from LR: LR BOOKED or later, not cancelled, no non-cancelled invoice, billing party resolved by payment type. DRAFT to ISSUED: tax computed from rule snapshot, number assigned, PDF queued, IRN requested if applicable. ISSUED to CANCELLED: invoice:cancel + MFA, reason, no active allocations, within statutory window; otherwise credit note. payment_status derived: UNPAID (paid 0), PARTIAL, PAID (paid = total).

### 8.4 E-Way Bill
PENDING to ACTIVE (success) | REJECTED (definitive rejection) | UNKNOWN (timeout/ambiguous). UNKNOWN to ACTIVE (reconcile finds it) | PENDING or REJECTED (reconcile confirms none). ACTIVE to CANCELLED (within window) | EXPIRED (sync).

### 8.5 Payment
RECORDED to REVERSED only, with reason and MFA; reversal deactivates allocations and recomputes affected invoices in one transaction.

### 8.6 Freight calculation (pure, versioned)
1. Inputs: charged weight and unit, packages, from/to locations, goods type, rate card for (party, date), selected charges.
2. Convert to rule unit (quintal = 100 kg, tonne = 1000 kg; package uses count).
3. Slab mode [CONFIRM]: WHOLE (whole quantity at slab rate, default) or INCREMENTAL.
4. freight = max(round2(quantity * rate), min_charge); FIXED unit: freight = rate.
5. charged weight = max(actual, minimum chargeable weight from rate card).
6. Charges: FIXED as entered; PER_UNIT = round2(quantity * amount); PERCENT_OF_FREIGHT = round2(freight * pct / 100).
7. Output calc_breakdown JSON (inputs, rule id, slab, intermediates, each charge, totals, calculator version) stored at BOOK; never recalculated.
Rate resolution: most specific match (location pair + goods type beats wildcards), then highest priority; party card beats standard card. No match: RATE_NOT_FOUND; override only with lr:override_rate, reason required, audited.

### 8.7 Tax (defaults; CA must validate)
Driven by tax_rule: party GST treatment, supplier state, place of supply, rate option. INTRA = CGST+SGST (half rate each); INTER = IGST; RCM = no tax collected with reverse-charge flag; EXEMPT = zero with reason. Copy rule into invoice.tax_rule_snapshot. Totals: sum of taxable lines + tax, then round_off to nearest rupee as its own line.

### 8.8 E-Way Bill rules (verify against current NIC rules; keep all thresholds in config)
Required above notified value (currently INR 50,000) for interstate and per state rules intrastate; Part-A consignment, Part-B vehicle; validity by distance (commonly 1 day per 200 km regular cargo); limited cancel window and not after in-transit verification; consolidated EWB groups several bills on one vehicle (maps to a challan).

## 10. GSP / E-Way Bill integration

GspPort methods: authenticate(gstin); fetchEwayBill; generateEwayBill; updateVehicle; extendValidity; cancelEwayBill; getEwayBillByDocument (reconciliation); generateConsolidated.
Typed errors: AUTH_FAILED, VALIDATION_REJECTED, DUPLICATE, NOT_FOUND, RATE_LIMITED, TIMEOUT, PROVIDER_UNAVAILABLE, UNKNOWN_OUTCOME. Only VALIDATION_REJECTED and NOT_FOUND are definitive; TIMEOUT/UNKNOWN_OUTCOME on a write moves the request to UNKNOWN.

**Generate flow**
1. API tx: validate LR state; insert or reuse eway_bill (PENDING); insert eway_request with key `GENERATE:<gstin>:<docType>:<docNo>`; enqueue eway.generate with singleton key; commit; return 202.
2. Worker loads request; if SUCCEEDED, exit; set SUBMITTED; attempts++.
3. Get GSP token (single-flight cache per GSTIN); call generate outside any tx with hard timeout (about 20 s).
4. Write raw exchange to gsp_request_log (credentials stripped).
5. Success: one tx sets bill ACTIVE with number and validity, writes eway_bill_event, request SUCCEEDED.
6. DUPLICATE: call getEwayBillByDocument and adopt the existing bill as ACTIVE.
7. VALIDATION_REJECTED: request FAILED, bill REJECTED, store provider message; no auto-retry.
8. TIMEOUT/UNKNOWN_OUTCOME: request UNKNOWN; enqueue reconcile; never regenerate directly.
9. RATE_LIMITED/PROVIDER_UNAVAILABLE (nothing accepted): backoff retry; per-GSTIN circuit breaker pauses attempts after repeated failures.

**Reconcile**: getEwayBillByDocument; found = adopt as ACTIVE and SUCCEEDED; NOT_FOUND twice with a delay = FAILED (NOT_CREATED) and allow manual retry; still ambiguous after max attempts = stay UNKNOWN in the attention queue.

**Credentials**: read by the worker role only from Secrets Manager via secret_ref; memory cache TTL 5 min; never in logs, DB, job payloads. LR booking and challan planning must work when the GSP is down (jobs queue and resume).

**Testing**: adapter contract tests against gsp-mock for every scenario; nightly run against the real sandbox.

## 12. Security

- Auth: Argon2id, lockout with backoff, rotating hashed refresh tokens with reuse detection, CSRF protection on refresh, TOTP MFA for sensitive roles, session revoke.
- API: TLS, WAF rate rules, app throttling on auth, Zod validation at every boundary, parameterized SQL, Helmet headers, strict CORS allow-list.
- Data: encryption at rest (RDS, S3 with KMS), private subnets, least-privilege IAM task roles, no secrets in env in production (Secrets Manager).
- Privacy: minimum personal data; no Aadhaar; retention policy aligned with DPDP; statutory retention for tax documents [confirm period with CA].
- Pipeline: dependency audit, container scan, secret scan.

## 13. Scalability, reliability, operations

- Capacity: about 5,000 LRs/day is a small fraction of one write per second; the real limits are GSP rate limits and correctness.
- Targets: reads p95 under 300 ms; book and invoice issue p95 under 800 ms excluding async; PDF ready under 15 s p95; availability 99.5% business hours; RPO 5 min, RTO 2 h (restore drill quarterly).
- Backups: RDS PITR 14 to 35 days; snapshot before each migration; cross-region snapshot copy optional.
- Alarms: 5xx rate, p95 latency, task restarts, RDS CPU/storage/connections, queue depth and oldest job age, UNKNOWN E-Way Bill requests older than 30 min, GSP failure rate, PDF failures, failed-login spikes.
- Optimize now: indexes, short transactions, async PDF and GSP, keyset pagination, N+1 detection. Later: read replica, partitioning beyond audit, Redis, OpenTelemetry, multi-region DR.
